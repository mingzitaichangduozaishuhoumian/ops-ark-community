# OpsArk 安全与执行约束

更新日期：2026 年 10 月 28 日

本文定义整体执行规则和验证要求。SSH/Web 持续观察、控制台告警和半自动单包批准通道已有实现。0.9 的预授权自动单包编排已在隔离 guest 完成真实升级及修复后验证。模型输入和权限遵守下文的数据边界。各环境的模式、提供方状态及验收范围以部署记录为准。[运行说明](RUNNING.md) · [验证记录](IMPLEMENTATION_NOTES.md) · [预授权自动单包编排](AUTOMATIC_REPAIR.md)

## 调查与持续防御

按需调查通过 SSH 读取目标主机信息。持续防御由本地检测与执行组件承担；控制台接收有界的事件与证据。原始高频事件先在本地聚合、去重和限量，再决定是否调用模型。

用户授权启用的既有规则在模型断网或超时时继续运行。调查受限应明确显示；模型或控制台失联不得成为关闭既有防护的理由。新动作必须经过执行端策略校验。

观察模式禁止 OpsArk 新建或扩大阻断，首次安装或接入组件不隐式启用封禁。已有防护组件按原授权策略继续运行，其实际动作与 OpsArk 记录的建议动作分别归档。

## 动作权限

| 类型 | 动作示例 | 授权要求 |
| --- | --- | --- |
| 自动调查 | 状态、资源、日志与配置检查，正常业务探测 | 在用户授权的目标与采集范围内执行，限制时间和输出 |
| 预授权单包修复 | Ubuntu 官方安全更新的精确单包事务 | 控制端与 root 同时核验目标/策略、包/USN、UTC 窗口、期限、次数与风险；未知或失败持续暂停 |
| 预授权防御 | 指定规则触发的短时来源封禁、已验证范围内的限流 | 策略包含目标、触发条件、动作、参数上限、期限、白名单、数量限制和撤销方式 |
| 逐次审批 | 配置修改与重载、重启或停止容器、隔离主机、结束进程、全局防火墙修改、凭据轮换、系统恢复 | 预览目标、差异、依赖影响、检查项与恢复条件，批准当前具体方案 |

仅按策略明确授权的动作可自动执行。产品规划不能代替部署用户对具体资产和动作的实际授权。

选择 automatic 不创建 grant，也不解除暂停。自动 grant 最长 24 小时，当前实现每次仅允许一个包变化，不允许高风险、未知风险或系统重启。可能的服务重启需显式预授权。失败、未知、验证不完整与重启待办保留原任务、占用配额并暂停；切换模式、换 grant 或重启不能清空这些限制。首轮实机范围仅为隔离 guest 的一次限定实验，不开放两台物理宿主的自动安装。

首版自动业务检查限定为无业务写入的探测。登录状态变更、下单、支付、回调重放等检查需要专用测试身份、测试流程和单独授权；未配置时标记为未覆盖，不生成真实业务交易来验收。

## 执行前与执行后检查

每项动作绑定具体客户或项目、主机、站点、服务、动作类型、参数及有效期。执行前检查目标状态、配置摘要、影响范围和冲突操作；前提发生变化或授权过期时，旧方案失效。

同一对象上的冲突操作串行执行。任务具有唯一标识，断线重试先核对已有执行状态，不重复实施未知结果的修改。

执行后分别记录命令或 API 返回、实际配置或规则状态、异常变化和业务检查。命令成功不能替代实际验收；验证失败保留证据并停止扩大动作范围。

配置回退应先验证备份存在、恢复方式有效及恢复对象正确。Nginx 重载需要绑定上次已验收生效的配置与版本；执行前备份的当前文件可能包含外部修改，不能直接等同于可靠回退点。缺少可验证回退版本时，首版仅交付诊断与人工处置材料。数据库迁移、数据删除和被入侵系统恢复使用各自的备份与恢复设计。

## SSH 与 Docker 权限

使用专用 SSH 账号和独立密钥，核验主机身份；按主机授权并支持撤销。私钥留在受控执行环境，禁止发送给模型或写入报告。控制台应有身份验证，并隔离客户之间的凭据、事件和模型上下文。

0.4 的[可选服务端入口](../deploy/readonly/README.md)已在两台明确授权的测试服务器验证：root 控制的公钥强制入口、精确命令表、受限 sudo helper、可信环境、关闭 stdin、输出/时间预算及继承到子进程的单机互斥锁。管理员安装和实验控制与应用只读权限分开；这不改变应用禁止 root 登记的规则，也不证明未安装的目标已有相同隔离。root 管理员和系统工具完整性仍是信任前提。

普通 Docker 环境的 `docker` 用户组具有 root 级权限。首版应优先以受限采集和结构化执行入口暴露必要能力，不将任意 Docker 或 Shell 权限直接交给模型。普通账号本身不能证明执行权限已受限制。[Docker 官方说明](https://docs.docker.com/engine/install/linux-postinstall/)

## 来源识别与防误封

启用自动封禁前，确认 CDN、代理及客户端地址的可信来源。未经验证的请求头不得直接作为封禁依据；共享出口和正常流量高峰应纳入观察案例。[Nginx 真实地址配置](https://nginx.org/en/docs/http/ngx_http_realip_module.html)

管理通道、必要的监控与业务回调需要明确保护或采用不同处置策略。白名单范围和变更应可审计，避免以大范围豁免替代来源校验。

验证实际流量路径，包括 Docker 发布端口、IPv4 / IPv6 与反向代理路径。只有验证过的路径才能开启自动动作。Docker 发布端口的流量可能绕过通常的 UFW 处理路径，应实测阻断位置与效果。[Docker 防火墙说明](https://docs.docker.com/engine/network/packet-filtering-firewalls/)

临时动作具有到期时间，并由本地执行端撤销，不依赖模型记住解封。支持人工撤销具体动作。怀疑误伤时检查新动作及业务变化，不能因单次健康检查失败就清空全部防护。

## 安全结论与已入侵主机

区分攻击尝试、疑似入侵和已确认入侵。高频请求、登录失败或高 CPU 均不能单独证明入侵；说明依据、证据缺口和下一步检查。

涉及主机控制权失陷时，主机日志和本地组件可能不再可信。保留已有机外记录，升级到人工响应、可信环境恢复和凭据处理流程，避免以杀进程或删除文件宣告清除入侵。

自动防御仅操作已授权资产和接入的防护服务。大流量导致上游链路耗尽时，提供证据及云厂商或边缘防护处置建议，不承诺单台 VPS 可完成清洗。

## 模型输入与数据保留

本节定义模型入口和备份通道的验收要求。各版本的覆盖范围以对应验收记录为准。

日志、请求、文件名和配置内容均作为不可信数据处理，不得改变工具权限、授权范围或执行策略。结构化输出同样经过参数与权限校验，不能仅凭模型返回内容执行命令。[OWASP 提示注入防护建议](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)

模型输入采用字段白名单。模型进程只接收本地采集器生成的服务标识、错误类别、计数、时间、漏洞编号和证据引用等结构化结果。私钥、令牌、密码、完整配置、数据库行、SQL 导出和原始日志留在受信任的数据处理程序内。模型身份不授予文件读取、数据库访问或任意上传权限。

向模型供应方发请求前，由独立出站入口校验来源、字段、类型和长度。遇到未知字段、敏感内容或无法分类的数据，拒绝整次发送，只返回阻断类别和本地证据引用。正则脱敏作为补充检查。审计记录供应方、字段类别、大小和判定结果，启用前展示实际发送范围。

异机备份走单独通道。源机的固定备份程序在加密后传输，备份接收方单独保管解密凭据。传输校验来源身份，恢复程序在隔离环境中核验完整性和历史摘要，返回状态、计数和校验结果。备份密文也不进入模型请求。

通用出站约束的验收应向每条模型入口注入合成私钥、令牌、SQL 导出及带敏感字段的日志，验证请求在到达供应方前被阻断。备份通道应分别验证密文传输、篡改拒绝和断网恢复。各路径按实测范围记录。

报告解释、SSH/Web 告警和整批/单候选漏洞分析共用同一模型出站检查。报告只发送事实类别、核验状态和临时证据编号。告警只发送分类、计数、相对时刻和临时事件编号。漏洞分析发送公告编号、覆盖和候选可用性，具体包版本与原候选身份留在本地。自动分析复用同一入口，源数据拦截发生在登记新模型预算前。模型服务凭据仅由传输层用作授权头。

SSH/Web 告警和漏洞分析的发送预览展示经过白名单的正文。报告解释的确认窗口展示模型、报告编号及发送的数据类别。历史记录保留原证据绑定，模型返回的临时编号经校验后在本地映射。新增诊断事实类别时，应同时更新摘要分类和拒绝测试。[隔离外发验收](../tests/test_ai_egress.py)

原始证据、脱敏片段、事件与审计分别设置保留期限、导出和删除规则。关键事件摘要及动作记录可保留到机外，访问权跟随客户或项目隔离。报告保留证据引用，避免将重复原始日志长期堆积。

## 资源和失效处理

- 采集限制命令时长、日志字节数、并发和磁盘扫描范围；资源紧张时减少检查。
- 事件洪峰下先聚合和限量，避免日志增长和模型费用反向拖垮主机。
- SSH 不通、权限不足、检测组件失联分别记录为检查状态，不能解释为目标健康。
- 模型不可用时保留规则防御、证据和人工排查入口。
- 控制台失联、执行中断和 TTL 到期均需要独立验证本地执行行为与恢复路径。

具体资源预算、保留时间和响应目标在实验环境测量后确定，并随支持环境公布。
