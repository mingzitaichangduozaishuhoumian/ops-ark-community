**当前缺口：** 固定 Nginx 实验不等于普通客户配置上下文已验证；应用配置自动修复、容器停止/重启/重建的产品执行及数据影响，不能用故障注入脚本或 APT 安装验收替代。当前不支持的动作不能标成已交付。

**容器重启的首个通道：** 单个完整容器 ID 由部署者登记，半自动模式下逐次批准。预览绑定目标、镜像、当前状态和批准期限。控制端和目标机记录原任务；回执丢失后查询原任务。此通道的实机角色和端到端验证需另留回执。 [部署说明](../deploy/container/README.md)

**应采证据：** 对计划内动作逐项明确对象、预览、影响、权限、备份/回退条件及原任务身份，再验证批准一次、真正执行一次、冲突/漂移拒绝、提交或回执中断后只查原任务、共享站点与数据影响。无可靠回退点或当前文件被外部修改时，应拒绝旧回退。先完成一项再增加下一项，不让模型获得任意 Shell。原计划未交付目标保持未完成，不能仅添加“不支持”说明就签成验收完成。

**应采证据：** 关联原调查、计划/审批、Root 原执行回执、同 ID 对账、边界之后的业务复验和导出摘要；核对执行与收费身份不重建、失败/超时仍待验收或明确失败，旧记录可查。用假密钥/令牌/数据库原文/未知字段逐入口检查整次拒绝与零外发，核对摘要无原日志、正文或敏感信息。备份交接独立核对可信收件人、密文哈希、另备凭据与镜像、断网恢复副本；目标 Root 账本的保留范围另列。已有充分证据可复用，不要求重复安装来制造新报告。

## 明确后续方向，不混入本次 MVP 已完成结论

- 公网/IPv6/Docker 发布端口的自主防御、长期 Root 许可续发、容器/宿主重启后的防护连续性及完整 WAF/EDR/SOC，继续按独立阶段验收。隔离 SSH 60 秒动作、22423 传输替换或[被保护监听器替换后的正确拒绝](../tests/defense_binding_loss_lab/README.md)，都不证明这些方向已完成；也不应等待所有新 Root 协议才收口现有诊断与处置任务。
- Debian 官方补丁、远端 ARM64 实机、Windows/macOS 被管理端、Rootless Docker、多层代理、多机依赖和多客户权限，按[平台矩阵](PLATFORM_SUPPORT.md)单独推进。控制台平台通过不扩大被管理端写入范围。
- 业务数据库/持久卷恢复、生产证书与 ACME 签发、站点迁移、登录/支付/回调等业务写入、DDoS 清洗及全天值守，属于独立适配或专项服务；控制端恢复和无副作用业务检查不代表这些已通过。
