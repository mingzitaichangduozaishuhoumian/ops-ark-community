## 迁移与数据来源

迁移没有直接复制活动 SQLite 主文件。先在不启用采集、不加载修复入口的候选中核对 API、权限、33 份报告、4 份基线、告警及三目标专用只读 SSH；随后停止 PC 临时控制端的实际监听进程和 CN 原观察进程，才取得最终一致性快照。

| 数据 | 权威来源与处理 |
| --- | --- |
| reports、baselines | CN 最终快照为主，与 PC 按 ID 合并；相同 ID 异内容拒绝覆盖 |
| security、web-security、security-ai | CN 最终快照整库保留，包括游标、去重表、通知次数、已阅及覆盖缺口 |
| patches、automation | PC 0.7 最终快照整库导入，保留任务、原执行范围、通知计数、修订号及未决提交登记 |
| 定期漏洞观察 | 新建独立数据库，按当前主机/策略作用域记录 |

`store_transfer.py` 使用 SQLite backup、完整性检查、表行数/行摘要和文件 SHA 清单。只有目标传输副本清除了固定 monitor lease；原库、事件、游标、通知、intent 未清空。两物理宿主的原 known_hosts 字节保持一致，作用域摘要没有变化；guest 使用独立主机密钥文件。

旧 CN 容器已明确停止，原镜像和数据保留为冻结来源；候选 smoke 容器也在新实例验证后停止，没有双活动控制端。切换后发生的新记录由 Intl 单实例写入。回退不能直接把新数据库交给旧 0.6 代码，应先冻结新实例并保留新增证据。
