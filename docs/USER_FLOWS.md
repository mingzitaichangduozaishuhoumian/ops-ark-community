# OpsArk 首版使用流程

更新日期：2026 年 10 月 26 日

本阶段交付可点击的离线原型，用于讨论接入、调查、动作预览和验收。原型中的主机、证据、检查和结论均为虚构数据，不代表已经接入服务器或完成故障测试。

## 网站接入

| 步骤 | 用户提供或确认的信息 | 进入下一步的条件 |
| --- | --- | --- |
| 登记主机 | 客户或项目、主机别名、SSH 地址、端口、专用账号、凭据引用 | 主机身份和连接状态可确认，已展示可读权限与缺失权限 |
| 确认依赖 | 域名、主机、Nginx 站点、上游、Compose 服务、共享依赖 | 不确定映射由用户补齐或确认；未知影响范围只允许调查 |
| 设置验收 | 无业务写入的地址、预期状态或内容、观察窗口、初始采集范围 | 明确未覆盖业务，默认只读调查与安全观察，用户授权对应采集 |

真实实现只保存凭据引用并使用受控执行环境。原型不接收密钥或密码，输入字段仅用于本地演示，刷新即恢复示例。

依赖识别失败时保存接入草稿，列出待补齐信息；权限不足时展示具体缺项，不能将连接失败显示为主机健康。已有防护的实际策略与 OpsArk 的观察模式分别显示。

修改主机信息后，原连接检查、依赖确认和验收确认失效，需要重新完成相应步骤；不能把前一个目标的确认沿用到新目标。

## 从域名或事件开始调查

用户可以选择已登记网站，或者从事件进入同一份调查。首屏显示受影响对象、当前状态、结论摘要、关键证据和未确定事项。

调查分成四个视图：

1. 调查结论：事实、候选原因、反证、缺失信息、依赖及影响范围。
2. 证据记录：按来源和时间展开原始片段，展示脱敏、截断、采集失败与覆盖范围。
3. 处置预览：动作、目标、参数或配置差异、依赖影响、授权与执行前提。
4. 恢复验收：动作是否生效、业务检查、正常访问影响、观察窗口与未覆盖项目。

当前原型演示四个事件：上游端口不一致、磁盘空间异常、容器反复重启和 SSH 暴力登录尝试。所有事件与报告样例使用相同标识，避免将原型虚构结果混入后续测试。

## 处置预览与停止条件

原型中的 502 样例展示 Nginx 请求端口与容器发布端口不一致。拟议的配置变更影响共享 Nginx 的两个站点，但缺少上次已验收生效的回退版本，因此执行入口保持不可用。

真实实现需要分别检查：动作是否有实现适配、目标是否明确、配置和依赖是否变化、当前授权是否有效、是否存在冲突任务，以及回退依据是否满足要求。

前提缺失时保留诊断与人工处置材料。用户输入“执行”不能绕过检查；证据补齐后生成新方案与新授权，不复用失效方案。

## 安全观察与预授权策略

观察模式仅记录触发条件、拟议动作和影响。现有 CrowdSec 等工具若已按原策略阻断，应单独标为外部实际动作，不能显示成 OpsArk 执行。

原型中的策略评审用于查看目标范围、来源可信度、管理地址保护及授权过期如何改变判定。切换评审示例不改变执行模式，不保存真实授权。

未来仅在通过实验验收后开放预授权防御：每份策略包含目标、触发条件、动作、参数和数量上限、到期时间、白名单与撤销方式。高影响动作继续逐次审批。

## 验收状态

| 状态 | 判断条件 |
| --- | --- |
| 待检查 | 尚未取得处置后结果，或本次仅完成调查 |
| 初步恢复 | 已登记的主要检查通过，但仍需持续观察或补齐覆盖 |
| 观察中 | 在事先确定的窗口内重复检查，保留每次失败与异常 |
| 已验收 | 动作与业务检查达到约定标准，观察完成，未覆盖事项已披露 |
| 未解决 | 异常仍存在、检查失败或无法达到事先约定的验收要求 |

原型中的“演示检查结果”仅切换虚构的验收展示，不执行 HTTP、SSH 或系统命令。它保留未覆盖业务及未完成观察，不把按钮点击当成真实验收。

## 需要用户验证的问题

- 从事件首屏是否能判断影响对象、主要证据和下一步？
- 是否能理解事实与候选原因的差异，以及为什么某些动作不可执行？
- 接入所需信息能否由日常维护者提供，权限要求是否可接受？
- 验收结果和未覆盖事项是否足以交给客户或开发者？
- 是否愿意再次使用，并为后续试用提供脱敏案例或测试环境？

访谈、真实服务器接入与故障实验尚待开展。流程原型的浏览器检查只验证界面交互，不作为诊断、防御或产品需求已经成立的证据。
