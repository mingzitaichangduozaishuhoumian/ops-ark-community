# 激活后恢复的 TCP 中断与回执验收

验收日期为 2026 年 11 月 4 日。实验构建固定在 `e4d8f0fe11aba9e3225169a777f07c4bff1b3a79`，沿用 `ff846f8` 的 0.17.0 运行代码。网络故障层、抓取脚本与产品文件分别留证。本轮范围是隔离客体网桥上的提交连接重置和查询建连丢包。

前两份隔离验收分别覆盖浏览器 HTTP 确认丢弃和已经解析的 Root 返回值未交给控制端。本轮从真实 SSH 连接和 TCP 包头核对中断点。[此前验收](ACTIVATION_RECOVERY_RECEIPT_LOSS.md) · [原 ID 对账规则](RECOVERY.md#已验证激活后的独立恢复017)

## 实验路径

每次运行使用单独的 Ubuntu KVM、受限 SSH 角色、账本和实验授权。控制端通过客体内部的私有网桥访问 TCP 中继，中继转发到客体原生 `sshd`。正常路径使用实际主机密钥认证和 Root 受限命令。实验观察层在发送已批准的恢复请求前，按原恢复 ID 和实际 TCP 四元组登记这一条连接。

1. 使用签名 Ubuntu APT 的 `libbrotli1` 旧版本作为前置条件。由观察任务按 `USN-8956-1` 自动安装官方修复版，保留原安装任务 `installed_restart_pending` 和活动暂停。
2. 在半自动模式单独批准普通测试服务激活。验证新进程和三份库的映射、新 SSH 连接及同条漏洞复扫，再切回手动模式批准独立恢复。
3. 中继继续转发真实请求，截断这条 SSH 连接的回程。核对 Root 同 ID 回执已落盘、对应暂停已解除且 RPC 锁已释放，再通过 Linux socket 的 abortive close 发送 TCP RST。独立的网桥抓取将无载荷的 RST 与已登记的四元组对应。
4. 控制端将原记录保存为 `unknown`，回执为空，本地暂停保持。停止实验控制端并备份自动化数据库，重启同一容器，确认原记录仍然未知。
5. 在客体内临时丢弃指定源地址到中继端口的新建 TCP 连接。查询同一个 ID，观察 SYN 重传和连接超时，确认仍为 `unknown`。撤除规则后再次查询原 ID，核对新的 TCP 握手、实际 Root status 和新的安全快照，本地状态随后成为 `verified` 并释放原暂停。

抓取仅保存 TCP 包头元数据。中继事件链保存端点、转发计数、回执摘要和时序。冷库保存未知及最终对账状态；归档下载后复核逐项 SHA256、SQLite 完整性及外键。

## 第一台隔离客体

实验 `c09e389a69b84a76` 使用 1 vCPU、1 GiB、无 swap。一次自动安装将 Brotli 更新至 `1.1.0-2ubuntu0.1`，一次获批服务激活将进程从 `9888` 切换至 `14297`。原父任务保持修订 7 待激活，独立激活记录达到修订 6 已验证。指定 USN 的确认受影响计数降到 0，复扫与激活记录建立了关联。

| 阶段 | 实测结果 |
| --- | --- |
| Root 已落盘，SSH 回程中断 | 中继抑制 14,736 字节 SSH 密文。网桥记录同四元组的无载荷 RST+ACK。控制端 HTTP 返回 200，状态为 `unknown`，回执为空，本地暂停仍活动 |
| 控制端重启 | 同一控制端容器的客体 PID 由 `10136` 变为 `16632`。冷库和重启后读取均为未知，Root 的原 ID status 计数仍为 0 |
| 查询建连丢包 | 一次原 ID GET 期间，同一 TCP 流发送 4 个 SYN，均命中丢弃规则，约 4.05 秒后仍为未知。规则撤除经检查确认 |
| 查询恢复 | 新流收到 SYN+ACK。一次原生 Root status 取回同一回执，控制端达到 `verified/local_released=true`。总计两次原 ID HTTP GET，只有恢复后的查询抵达 Root |
| 最终状态 | Root 恢复提交 1 次，安装、服务重启各 1 次。原安装、激活和 Root 回执摘要在对账前后分别一致，已用配额 1/1、实验手动模式修订 3 |

恢复 ID 为 `c315af5f40809e450a14a5d62b5166fd`，Root 原始回执 SHA256 为 `d9cddbe174adcc2a69d6d56f97494c92e33af66b40111f9d6b1a439a0e8c9da7`。归档包含 268 个文件、175 个中继审计事件和 769 条 TCP 包头，压缩包 SHA256 为 `ac5be99edf96d2cc84a3f5aadcb53af930704de66a5ad0d37b027c4c917114d4`。

首次激活预览返回 409，Root 中的激活计划和执行记录当时均为空。随后观察到 PackageKit 与 fixture 都映射旧库。PackageKit 自然退出后才新建预览并批准一次。取证脚本原来假定一条激活通知，本轮实际记录两条，修正后从原激活继续取证。对账之前，三份查询中断证据在 root 私有目录内由 `0644` 收紧至 `0600`，逐项 SHA 保持，原取证失败和续行记录均入档。恢复链路的原 ID GET 在权限核对通过后发出。

功能验收完成后结束资源采样，共 767 个样本、约 25 分 37 秒，内核 OOM 计数为零。该采样作为本轮资源记录归档。归档下载验证完成后清理了 VM、临时密钥、令牌和启动介质，宿主旧 18 个容器的镜像及运行状态与实验前一致，原 Root 文件、策略、模式和启动身份均核对通过。

## 第二台隔离客体

实验 `e485c3db822e1163` 使用另一份独立的 1 vCPU、1 GiB KVM 和新的实验账本。PackageKit 自然退出后，两次检查均只发现原 fixture 映射旧库。首次激活预览通过，批准一次，服务进程从 `9657` 切换至 `14024`。新 SSH、三库映射和同条 USN 的复扫通过，受影响计数降为 0。控制端保留实际两条激活通知。

| 阶段 | 实测结果 |
| --- | --- |
| Root 已落盘，SSH 回程中断 | 中继抑制 14,736 字节 SSH 密文，记录同四元组的无载荷 RST+ACK。控制端保存未知、空回执和活动暂停 |

| 对账 | 同一 ID 总计两次 HTTP GET，其中一次原生 Root status 到达。控制端最终 `verified/local_released=true`，原安装、服务激活与恢复各一次，额度 1/1 |

归档离线复核后，清理了实验 VM、临时凭据、含密钥的启动介质和本轮工具镜像。宿主旧 32 个容器的镜像、身份与运行状态，以及原 Root 文件、策略、模式和启动身份，均匹配前置快照。
