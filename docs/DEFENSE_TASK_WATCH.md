# 原防护任务的只读跟进

这是开发分支的可选能力，默认关闭。它只跟进已经提交过 apply 意图的原防护任务，使用既有 readonly 身份查询同一 RID，保存状态变化并在控制台告警。它不会 arm、prepare、apply、revoke、更新许可、重设配额或调用模型，也不表示持续自动防御已经开放。现有 `OPSARK_DEFENSE_WORKER_ENABLED=true` 仍拒绝启动。

## 部署端明确启用

只用于已经完成独立 SSH 防护登记的实验部署。先保留原 inventory、policy 和独立凭据引用，再由部署者给该控制端进程设置：

```text
OPSARK_DEFENSE_TASK_WATCH_ENABLED=true
OPSARK_DEFENSE_TASK_WATCH_HOSTS=registered-host-id
OPSARK_DEFENSE_TASK_WATCH_INTERVAL=60
```

目标必须显式列出、无重复且已经登记，最多 10 项；间隔为 30 至 3600 秒，默认 60 秒。非法开关、类型、目标或缺失独立登记会被拒绝。网页只查看状态、打开原任务和标已阅，不能改变部署端开关。手动模式仍能只读跟进，不因此新增执行权限。

当前支持显式 Settings 或进程环境变量。固定 Compose 模板和加密交接 v2 的固定 overlay 没有增加新变量透传，不能只把这三行写入 Compose 的 `.env` 就声称已启用。需要部署材料与恢复合同扩展时应单独审核，不能悄然改变旧模板。

## 状态、告警和预算

任务和跟进记录共用现有 `security.sqlite3`，仍为十库。每 tick 最多一次 RPC，全局串行；跨进程租约、claim 和提交都有 owner/epoch 核对，旧 owner 不能发布晚到结果。发送前复核停止状态、原清单、目标和公共 pin；回执写入原事务库时在同一 SQLite 写事务内再次核对 lease/claim。取消的本地工作不伪造成服务器不可用。

每个原任务最多 24 次尝试、每 UTC 日最多 8 次，本地门禁取消也保守计入；这些计数不是成功或实际上网的次数。次数和退避跨重启保留，失败退避有上限，达到预算或容量后明确停止或延后，不通过换任务、换 owner、标已阅或重启来重置。最多保存 2048 个跟进任务、4096 个状态事件，达到容量不会静默删旧历史。

首次启用时按 apply 请求的稳定 rowid 分页登记，每 tick 最多 32 条，跳过的其他目标记录也会推进游标。大量历史需要追赶，`discovery_incomplete=true` 时必须保留“仍在分批登记”的提示；暂无事件或 pending=0 不代表完整扫描、目标健康或业务恢复。

查询时点受间隔、分页、退避、旧租约和 claim 到期影响，不提供即时性 SLA。首次确认已到期也不补造曾生效的可信回执；缺少原执行证据时继续待验收。

相同状态不重复告警，状态变化才追加记录。准备状态不作永久终态，因为原发送者仍可能在途；之后出现未知回执仍须继续跟进。到期、撤销和异常分别显示。标已阅只更新该事件的确认时间，不清 latch、不退款、不续期，也不使业务复验通过。

告警仅采用固定状态、控制端 UTC、任务摘要引用及本地准确的原任务链接，不包含异常原文、日志、配置、密钥或数据库原文。当前通知渠道为控制台；不会自动复用其他用途的 webhook 或向外部模型发送材料。

## 本地接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/ssh-defense/task-watch` | 读取开关、运行、追赶、容量和固定原因状态 |
| `GET /api/ssh-defense/task-watch/events` | 用 after_sequence/limit 分页读取状态事件 |
| `POST /api/ssh-defense/task-watch/events/{event_ref}/ack` | 严格 `confirm_ack:true`，只标记该事件已阅 |

全部接口沿用控制台认证。无授权、无效正文和不可核实的记录不会回显输入。停止工作器会阻止新发送和晚到结果提交；已经开始的只读 RPC 可以在其传输时限内结束，不承诺撤回已经在途的网络操作。

## 恢复与权限边界

新表、游标、次数、事件及确认状态跟随现有数据库备份。旧库启动可以新增已知表和索引，但不改旧记录、rowid、模式、审批、费用或权限。恢复工具仍只输出待审材料，不启动控制端、不载入或执行原 `.env`；独立凭据不跟随，配置须由部署者审查后明确使用。原配置字节即使保留新开关，也不代表恢复过程已经启用它。

部署者停止旧实例后，新的控制端仍只查询原 RID，不接管旧发送 owner，也不重放旧意图。目标或公开信任材料漂移时保留缺口并停止该跟进，不能转向别的主机。业务是否恢复仍由独立业务复验确认；Root 状态和告警已阅均不能代替业务验收。

更长期的观察、自动动作和 Root 授权生命周期继续按[工作器阶段计划](SSH_DEFENSE_WORKER_PLAN.md)单独实现和验收。两台真实 SSH 提交中断、该只读工作器的实机范围和其他平台覆盖，必须依据各自结果记录，不能由本页的本地合同推导。

两台已完成[真实后台线程与三独立进程验收](../tests/defense_task_watch_lab/README.md)：每侧一次原 apply、三个自动只读查询，手动模式继续至到期，已阅及第三进程重启保留预算与事件；没有手动 HTTP query 替代，没有业务复验，摘要保持待验收。真实提交后、未知回执落库前退出另有[双机记录](../tests/defense_abrupt_process_lab/README.md)。这些记录不扩充为长期自主防御。
