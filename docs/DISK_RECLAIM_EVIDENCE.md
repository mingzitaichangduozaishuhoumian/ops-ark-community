# 磁盘 inode、开放文件与条件容量证据

磁盘只读调查可由部署者启用精确目录/PID 范围的元数据采集。固定 helper 只用目录枚举、`stat/fstat`、`readlink` 读取文件系统和 `/proc/<已登记PID>/fd` 元数据；不打开普通文件内容，不读日志正文、环境、密钥、令牌、数据库或卷正文。范围文件本身是唯一读取正文的管理员配置。采集无删除、截断、信号、重启、回收或模型调用。

已启用时，原来固定广泛目录的 `du` 被此证据替换；容量/inode `df` 保留。未启用的主机维持旧覆盖与未核实缺口。调查详情现有事实/缺失/证据区域及 Markdown 导出展示相同的对象引用、条件和数字；没有清理按钮。

## 管理员的明确登记

目标机 root 创建 `/etc/opsark/disk-reclaim-scope.json`，文件 root 拥有、0600、单硬链接，父目录 root 拥有且其他用户不可写。示例仅说明结构，不能直接替代真实目录归属与 PID 授权：

```json
{
  "schema_version": 1,
  "directories": [
    {"path": "/srv/site-logs", "category": "log"},
    {"path": "/srv/site-data", "category": "business"}
  ],
  "process_ids": [1234],
  "max_depth": 2
}
```

`log/business` 是部署者声明，不从文件正文推断。业务、数据库和持久化文件必须登记为 business，任何状态的 business 对象都排除容量估算与清理。当前切片只覆盖与 `/` 相同设备的目录，不跨挂载点；目录必须是绝对、精确、非重叠、至少两级的 ASCII 安全路径，禁止 `/etc`、`/proc`、`/sys`、`/dev`、`/root`、`/run` 数据树。目录和文件不接受符号链接。内存映射和其他内核引用不扫描，未登记进程不扫描。

至多 8 个目录、32 个明确 PID、8 层深度、全局 512 个目录条目/512 个 FD、32 个唯一常规文件对象，输出最多 14,000 字节。helper 内部单调时钟 3.5 秒/闹钟 4 秒，外层 timeout 5 秒。所有登记 PID 的常规文件 FD 必须落在这些目录和深度内；发现范围外常规文件、敏感文件名、未知文件类型、跨类别硬链接、跨设备、权限不足、目录或 FD 变化、深度/数量/输出上限、超时，整份结果拒绝。套接字、管道、设备和 kernel anon FD 不作常规文件占用证据。不能因拒绝而扩大目录或 PID 范围；先核实所需范围与进程持有关系。

PID 会变化且可能复用，部署者须更新精确范围和独立核对的摘要；网页/API/模型不能提交路径、PID 或任意命令。采集没有证明 PID 的业务身份，输出只称登记进程。进程退出、FD 关闭/新增、对象改变或扫描中发生竞争会拒绝；快照仍是非原子观察，不保证返回后没有变化。

核对 scope 原始字节的 SHA256，在现有主机 TOML 中增加：

```toml
disk_reclaim_scope_digest = "<服务器端范围原始字节的64位SHA256>"
```

只允许 `opsark-readonly` 专用账号。按既有 `deploy/readonly/export_policy.py` 导出并安装该主机精确策略，磁盘范围启用后只增加这条无参数 helper 命令、移除旧磁盘 `du` 命令：

```text
LC_ALL=C timeout -k 1s 5s /usr/local/libexec/opsark-disk-reclaim
```

管理员使用审核过且 root 拥有的源码运行专属安装器：

```text
python3 -I /absolute/reviewed/deploy/readonly/install_disk_reclaim.py --scope /absolute/reviewed/scope.json --expected-sha256 <独立核对的SHA256>
```

安装器要求已安装策略含精确命令，安装 root-owned helper、0600 scope 和完整性标记；无标记/漂移现存文件拒绝，更新中断只接受标记中的旧/新摘要。它不创建账号、不改 sudo/SSH/组/业务配置、不重启。目标机源码与策略部署由管理员完成，本分支未执行任何实际安装。

## 能证明的占用与估算条件

每个唯一 `(st_dev, st_ino)` 只产生一个对象；同 inode 的多个硬链接和多个 FD 不重复相加。对象返回由 scope 摘要、设备/inode、ctime 纳秒绑定的 SHA256 `object_ref`、`directory-N`、`process-N`、逻辑大小、`st_blocks×512` 已分配字节、链接计数、范围内链接计数及闭合状态。ctime 变化会改变引用，防止沿用已变化对象或复用 inode 的旧引用。正常采集不返回 PID、设备号/inode、原始/相对文件名、路径、任意文本或内容。`directory-N`/`process-N` 分别对应 root scope 中目录顺序/递增 PID 顺序。

| 状态/类别 | 容量估算与释放条件 |
| --- | --- |
| 已链接日志、所有硬链接均在范围内 | 当前文件分配块可列入条件上界；须审批保留要求、移除全部链接并释放全部持有者及映射 |
| 日志仍由登记进程打开 | 同一 inode 不重复累计；删除文件名也不保证释放，须全部引用释放 |
| 已删除日志仍有 FD | `st_nlink=0`、kernel FD deleted 标记及已分配块共同提供证据；再删路径无效，须全部持有者/映射释放后重测 |
| 硬链接数大于范围内链接数 | 仍列当前占用，排除条件容量上界；不授权访问或移除范围外链接 |
| business，包括已删除仍持有 | 仅列占用证据，估算贡献恒为 0，始终不是可清理项 |
| 登记 PID 中没看到 FD | 仅说明这些 PID 中未见；不证明全机无人持有，不能据此承诺立即释放 |

条件区间的下界恒为 0，上界仅为可分类日志对象的已分配块之和；稀疏逻辑大小不进入上界，不计算目录/文件系统元数据。`immediate_reclaimable_bytes=null`、`physical_reclaim_verified=false`。共享/reflink 块、快照、压缩、未扫描引用和并发写入可能使实际物理释放为零。上界是当前文件分配块的有条件估算，不是立即可用容量、自动清理计划或处置后预测。`df` 可用容量、文件分配块及真实处置后的物理变化须分别测量，不能相互替代。

## 同一范围的增长来源对照

在原“保存为观测基线”流程中，新元数据同时提取 `disk_scope` 分配块指标：登记范围全局总量、log/business 分类总量，以及“类别＋有序目录引用组合”总量。比如一个 inode 的两个硬链接分别在 directory-1 和 directory-3，只进入 `log / directory-1+directory-3` 这个组合一次，不同时加进两个单目录，也不让全局/类别总量翻倍。全局、类别和组合是同一占用的不同汇总层次，不能再相加。证据和基线只存 opaque 目录引用及类别，不存路径、PID、文件名、object_ref 或 inode。

后续同主机、同场景、同 scope 调查在原报告“观测基线与变化”和 Markdown 导出中显示哪个类别/登记目录组合增加或减少了多少已分配字节；保留原报告和当前证据引用。使用同一 scope 的两个完整、通过白名单核验的元数据扫描时，某个组合未出现才可按零观测对照新增/消失。scope（包括目录分类、PID 范围）变更停止比较；超时/缺证据不当作零。启用前的旧基线没有这些字段时显示缺口，须保存新基线，不倒填历史。

该对照仍是登记范围中的非原子快照，不覆盖全机或连续增长率。`object_ref` 带 ctime，写入或链接改变会变化，因此基线不按 object_ref 连续追踪某个文件。目录组合变化还可能由移名/硬链接成员变化造成；组合上升不能单独证明单文件因果。业务数据的增长只作占用事实，始终不推导清理；分配块下降也不证明物理空间释放或业务恢复。

新指标命名、算法版本、512 字节单位、数值范围、类别/组合加总采用闭合契约；未知指标、重复/乱序目录引用、缺少分类总量或不一致加总整份对照拒绝，不显示局部差异，并阻止本次模型解释。导出和模型投影再次核对新指标与当前元数据/证据绑定。模型仍只接收原白名单的对照状态、差异数量及证据别名，不接收指标名、目录组合、大小、路径或其他新数据，不增加传输入口。

## 仅管理员本地定位对象

SSH 报告的“证据记录 → disk_reclaim”提供各对象的“选中本地定位命令”。页面只选中可复制文本，不提交执行，不请求额外 API。目标机 root 管理员在本地终端运行该固定 helper 的独立模式：

```text
/usr/local/libexec/opsark-disk-reclaim --locate-ref <对象64位引用> --expected-scope-sha256 <范围64位摘要> --expected-snapshot-sha256 <证据快照64位摘要>
```

参数必须按此顺序且都是精确 64 位小写十六进制。模式要求 root、读取原 root-owned scope、使用同一完整元数据扫描并重新验证 scope/整份快照/对象引用。范围变更、任一对象改变或消失、伪造引用、敏感/未知/越界对象、权限/数量/时间限制，整次不给定位映射；重新调查后再取当前命令，不能删去核验参数。没有单独路径输入、内容读取或写入动作。

定位成功只在管理员终端打印该对象的当前范围内硬链接路径、已登记 PID/FD 与已删除对象的最后路径；已删除路径只是历史名称，不是可删除的实体。映射不保存、不进入正常采集返回；不要把它上传到控制台、模型或客户报告。模式不改变 business 排除、保留审批或释放条件，不生成删除、截断、信号或重启命令。

该带参数命令**不在**精确 SSH 策略中；Web/API/模型工具只能调用原来的无参数采集命令。定位输出使用独立 `opsark-disk-object-location-local/v1` schema，正常证据 DTO 不接受它。即便异常传输把映射放进调查，控制端会清空结果、整次阻断模型，报告和导出均不保留映射。非 SSH、失败/截断/未绑定/外发阻断的报告不展示定位步骤。

## 外发与失败

目标机仅输出闭合 schema、整数、枚举和证据引用；错误只输出固定 reason。控制端核对范围 SHA、快照 SHA、重复/未知字段、严格类型、对象唯一性、块单位、状态/链接/持有关系、业务排除与加总一致性。失败原文不写报告，只留固定拒绝/超时说明；不保留局部估算。失败标记随报告保存，即使前置脱敏已经移除敏感字符串，也会整次阻止模型解释。

新证据仍经原 `diagnosis` 门禁与原 provider 传输。模型只收到既有的类别和证据别名，例如 `disk_object_metadata` / `disk_conditional_reclaim_bound`，不收到对象路径、PID、scope SHA、对象引用、文件大小或正文；没有新模型入口。普通报告与导出也没有路径或未分类数据。
