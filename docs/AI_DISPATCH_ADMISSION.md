# 自动 AI 发送准入与模式切换

自动分析的预算意图与实际发送许可分别核对。意图先持久保存，以免断线或重启造成重复请求；它不代表后续模式、证据或许可变化可以被忽略。

## 发送边界

自动流程在取得独立预算意图后立即复核一次，并在共享提供方入口完成白名单投影、请求结构校验和编码大小检查后，再复核一次。最终检查通过是本地发送准入点。

复核绑定当前模式及修订、同步状态、控制策略、自动 AI 许可、提供方、原候选与扫描、输入摘要、请求所有者、意图状态、截止时间和停止信号。模式锁只用于非阻塞的本地检查，网络请求期间不持有该锁。正在同步或无法核实锁状态时停止本候选的新外发。

准入前已生效的撤回或证据变化会阻止联系提供方。意图和预算保留，自动账本记为失效并记录阻断；同一候选不会因此退回次数或自动重发。原生计划和安装仍要通过各自的独立授权与证据核验。

最终准入后，请求按在途处理。后续模式变化不承诺取消已准入、已发送或可能已计费的网络请求；返回结果也不能绕过后续的模式、证据及原生执行检查。此边界不提供跨本地事务与远端网络的原子取消承诺。

## 与手动建议和防泄密的关系

发送检查通过调用范围内的本地上下文传递，回调不进入消息正文、配置、数据库或模型响应。退出或异常后恢复调用方上下文，后续独立手动调用不保留此次自动检查。Python 创建的异步子任务可能复制创建时的上下文，因此自动调用不能在此范围内派生延迟执行或脱离原调用的后台任务；当前路径同步完成分析，再退出该范围。

明确确认的手动分析保留原有入口，不因自动模式正在同步而被整体禁用。所有调用仍先经过同一个白名单外发门禁，提供方适配也不能跳过它。拒绝自动准入不等同于外发数据违规，两者分别记录。

## 本次复核与验证

在未修改的 `d8a02f2` 上，使用临时合成数据库、真实并发模式切换和 `httpx.MockTransport` 重现了以下次序：

```text
后台核对 automatic + 已同步
  → 保存模型预算意图
  → 管理员切换 manual，Root 模式确认尚未返回
  → 原代码仍序列化一次分类摘要请求
  → 返回后核验拒绝采用结果，不生成原生执行证明
```

稳定自动模式、进入流程前已待同步、意图保存后才切换模式三个对照，原代码的提供方请求数分别为 `1 / 0 / 1`；修复后的独立复现为 `1 / 0 / 0`。复现没有访问真实提供方、读取部署凭据或提交原生修复。

这确认了发送许可与模式切换的一致性缺口。它没有证明未认证攻击者可以控制模式，没有绕过分类白名单，也没有发生原始密钥、日志、数据库内容泄露或原生执行越权。

按 `fp-check` 的可利用性门槛，复核统计为 **0 项已证实可利用漏洞、1 项 FALSE POSITIVE**：触发条件依赖已授权的自动任务与管理员模式变更，未证实新的攻击者能力或可利用安全影响。这里的 FALSE POSITIVE 只针对可利用漏洞结论，不否定已重现并加固的策略一致性问题。
