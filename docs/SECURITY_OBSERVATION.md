# 持续 SSH 安全观察与控制台告警

更新日期：2026 年 10 月 28 日。0.5 默认不启用后台采集，部署者必须明确指定已登记主机。当前只支持 SSH 认证事件；Web 扫描、流量分析、外部推送和封禁均未实现。

## 部署和启用

先按[受限接入说明](../deploy/readonly/README.md)安装专用账号，再将 [read_journal.py](../deploy/security/read_journal.py) 作为 root 所有的 `/usr/local/libexec/opsark-security-read` 安装。重新导出并审核策略，新增的唯一命令为：

```text
LC_ALL=C timeout -k 1s 5s /usr/bin/python3 -I /usr/local/libexec/opsark-security-read
```

调用者不能选择 journal 路径、unit、任意参数或 Shell。更新策略不是给采集账号增加通用 sudo，也不需要修改主 SSH 服务。仅登记主机并不能替代服务端安装及拒绝验收。

| 环境变量 | 约束 |
| --- | --- |
| `OPSARK_OBSERVE_ENABLED` | 默认 `false`；明确 `true` 或 `1` 才启动 |
| `OPSARK_OBSERVE_HOSTS` | 逗号分隔的唯一登记 ID，最多 10 个，不接受临时 IP 或自动选择全部资产 |
| `OPSARK_OBSERVE_INTERVAL` | 默认 60 秒，可设 30–3600 秒；属于轮询目标间隔，不是响应 SLA |

开启观察但没有目标、目标未登记、重复 ID 或非法间隔会拒绝启动。应用仍运行单 worker；后台观察与手动调查共享采集锁。同一数据库的观察进程使用持久租约，每个主机采集前和入库前续租，避免重复进程并行采集。

[VPS 常驻部署](../deploy/observer/README.md)使用独立的非 root、只读文件系统容器，绑定主机 loopback，状态和凭据分别挂载；凭据挂载只读，不挂 Docker socket。关闭浏览器或本机电脑后，VPS 上的观察与入库继续运行。当前通知渠道只有控制台，关闭页面期间不会另发邮件或聊天消息。

## 采集范围与证据

固定读取最近 15 分钟的 `ssh.service` 和明确的实验 unit，最多 200 条 journal 记录。读取受 4 秒和 256 KiB 原始输出预算限制，向控制端投影最多 80 条认证事件和 12 KiB JSON。达到记录/输出上限、权限不足、格式不支持、来源不可信或时钟超出预算都会显示缺口，不能解释为没有事件。

journal 子进程还有独立的 3 秒 timeout 及 1 秒强制终止宽限。全局采集锁逐层继承到 timeout，避免 reader 被强制结束时提前释放锁或留下失去监督的日志进程；新请求在已有执行存活时失败，不并发扩大工作量。

来源校验使用 journal 提供的 unit、可执行文件及进程名；不能只信任调用者可以设置的 `SYSLOG_IDENTIFIER`。字段信任边界见 [systemd journal fields](https://www.freedesktop.org/software/systemd/man/latest/systemd.journal-fields.html)，固定时间窗及 JSON 查询参考 [journalctl](https://www.freedesktop.org/software/systemd/man/latest/journalctl.html)。系统和 root 管理的工具完整性仍是信任前提。

只识别完整的 Failed/Accepted password、publickey、keyboard-interactive 认证结果。VERBOSE 的 `Accepted key ... found at ...` 属于审计说明，不作为另一次登录，也不产生格式缺口；未知的真正认证方法仍保留缺口。

控制端只保存时间、来源 IP、认证方法、账号类别（root/invalid/other）、可信 unit、journal cursor 及稳定 ID，不传输或保存原始 MESSAGE、实际账号名或密钥内容。管理员可依据 cursor 在授权主机复核；这些投影不是完整取证备份。

事件 ID 绑定登记范围摘要与 journal cursor。重叠轮询和控制端重启不会重复计数，冲突标识会停止该批计数。首次只覆盖可见的 15 分钟；离线跨过可见窗口、明显时钟回退、来源或格式异常均有独立缺口。原始记录可能轮转或丢失，完整采集也不等于整机安全。

## 规则与已阅

- 同一来源 IP、登记范围和来源类别，在滚动 15 分钟内至少五条去重认证失败记录，产生关注告警。
- 至少五条失败之后出现成功认证，产生独立的高关注告警。共享出口和合法任务也可能产生该模式，不能据此认定入侵。
- 记录条数不等于独立连接数、人数或攻击者数量。`current_window_count` 是告警最后一次新增证据所关联的窗口计数，不是浏览器当前时间窗的实时值。
- 不完整观察和采集失败分别产生告警；相同失败反复轮询不会每轮增加通知。恢复采集不删除历史证据。
- 认证告警只有新增的独立事件才可能再次通知；冷却期 600 秒。没有新事件时，重复轮询和重启均保持原计数。
- “已阅”只保存操作员确认，不能代表风险解除、故障恢复或封禁撤销；新的证据满足通知条件时可再次变为待阅。

`system_ssh`、`controlled_probe` 和 `collector` 三种来源分别显示。实验事件始终标注“实验演练”，不会转为真实攻击认定。模型不参与规则触发，告警也不调用修复或封禁。

## 接口与保留

以下接口均需 Bearer 认证，已阅操作还受同源和请求长度限制：

| 接口 | 结果 |
| --- | --- |
| `GET /api/security/status` | 是否启用、进程状态、轮询间隔、目标最近读取/下次时间、覆盖状态 |
| `GET /api/security/alerts` | 最新 100 条告警摘要，包含来源、已阅状态和通知次数 |
| `GET /api/security/alerts/{id}` | 告警、最多 20 条保留事件及仍在保留期内的关联观察 |
| `POST /api/security/alerts/{id}/ack` | `{ "acknowledge": true }`；仅更新本地已阅状态 |
| `GET /api/security/observations/{id}` | 有界的安全投影与缺口；过保留期返回 404 |

普通事件保留 24 小时且每个主机范围最多 10000 条；每条告警最多保护 20 条证据。观察记录每个范围最新 100 份，告警总量最多 1000 条，列表只返回最新 100 条。旧观察摘要过期后，仍保留的告警事件不能被误称为完整原始日志。

控制台仅在已登录、页面可见且停留于安全观察页时每 15 秒刷新；离页、隐藏或退出会停止界面轮询。退出控制台不会停止 VPS 的后台观察。失败、过期、租约待接管和未启用状态分别显示，不以列表为空代替健康证明。

## 两台测试服务器的验收

两台均安装了投影 helper，精确策略从 14 条增加到 15 条，旧命令未扩大。第一台部署持久控制端，同时观察自己及第二台；原报告与基线通过 SQLite backup 一致性迁移，访问令牌和独立采集密钥只进入受控运行环境，管理员密钥没有复制到服务器。

现有 Fail2ban 匹配 `_COMM=sshd`，所以演练使用与系统 sshd 同哈希的 root 管理副本、独立进程名和 unit，且只监听 `127.0.0.1:23999`。先验证实际 journal metadata，再在该端口生成每台五次失败及一次合法公钥认证；不向主 SSH 端口制造失败，也不修改或停用现有防护。

自动观察生成四个带事件证据的演练告警。新一轮重叠采集、已阅和控制端重启后，事件/通知计数保持不变；临时移走仅供观察的 helper 时，两台显示不可用并有采集失败告警；恢复文件后重新取得完整结果。实验 unit 已停止，观察继续运行，原实验业务容器保持运行。

实机发现并修复了两个问题：私有源码目录权限随 Docker COPY 进入镜像，需保证应用资产可被非 root 进程读取和遍历；VERBOSE 密钥审计行必须与认证结果区分。没有为了让指标变绿而丢弃真正未知的认证格式或来源缺口。

本次安全观察的验收回执私下保存，原始运行资料和凭据不提交 Git。Web 安全事件、外部推送、生产规则准确率测量及预授权防御仍待后续阶段。
