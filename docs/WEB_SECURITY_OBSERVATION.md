# Web 持续观察与 AI 建议

更新日期：2026 年 11 月 5 日。

## 原生预算与不可用验收

2026 年 11 月 5 日，`0.18.0` 私有候选 `f8cfeff` 在新的 Ubuntu 24.04 KVM 客体中完成实际 Nginx、systemd/journald、受限 SSH 和真实控制台 API 的联合验收。客体为 1 vCPU/1 GiB，控制台镜像内 74 个运行文件与候选逐一一致，没有挂载源代码或 Docker socket。

20 次正常请求完整采集且无 Web 告警。随后 240 次受控请求包含 216 个 200 和 24 个固定 500，敏感路径分三类各 8 个，最多并发 2、每秒最多启动 19 个请求。原生 reader 读取 200 条原记录，裁剪后投影保留 25 个分类事件，输出 12,199 字节，明确标记记录数、事件数和输出字节三类预算缺口。原始 journal 记录不随该投影输出。控制端保留 24 个扫描事件下界，未依据降级样本生成错误比例告警。

重复轮询和控制端真实重启后，扫描事件和通知计数保持一致。仅临时停用新客体只读账户的公钥时，通道明确变为不可用并保留旧证据；管理账户仍可用，原公钥逐字节恢复后重新观察通过。一次明确确认的本地 503 模型分析只发送了一份经过门禁的分类摘要，失败没有缓存为成功，规则观察继续运行。七个阶段和九条不可变历史观察分别留证。

请求与响应均由新客体的固定实验站点产生。此项覆盖受控日志预算、只读认证不可用及一个固定模型错误路径，生产吞吐、物理网络中断、模型超时、所有供应方和真实模型效果继续单独验收。完成后本轮容器、网络、覆盖盘、镜像、远端私有目录和本地新管理私钥已清理，原有资源保持一致。复现资产与步骤见[预算实验](../tests/web_budget_lab/README.md)。

## 事件、来源和规则

Nginx 内部把路径和客户端声明映射为有限类别，新观察流只保留时间、方法类别、状态、延迟、字节数、请求标识及来源判断，不保存原始 URL、查询参数、正文、Cookie、Authorization 或原始 User-Agent。自称爬虫不构成身份验证，也不会豁免规则。

| 规则 | 当前条件 |
| --- | --- |
| 敏感路径扫描 | 15 分钟内同站点/来源至少 5 个不同事件、覆盖至少 3 类敏感路径；不等于成功入侵 |
| 错误集中 | 当前完整快照中最近 300 秒（5 分钟）的窗口、至少 10 条非健康检查请求、至少 5 条非预期 5xx 且比例至少 50% |
| 响应变慢 | 同样要求当前完整窗口及样本量，记录至少 2 秒的慢请求；不据此断言根因 |
| 采集失败与覆盖缺口 | 单独保留不可用、裁剪及来源问题；不将采集失败当成安全 |

不按请求量单独断言攻击。明确标记的预期维护错误不计入非预期错误比例。站点聚合告警不归咎于单个客户端。

直接连接使用可信对端；转发头仅在显式登记并核实代理链后参与来源识别。未知代理来源不能用于封禁整个网关。当前实验不信任调用者提供的转发头。

## 采集和保留

部署资产见 [deploy/web](../deploy/web/README.md)。管理员安装 root 所有的固定 reader、配置和策略，只读账号只增加一个精确采集命令，不取得任意 Shell、Docker 组或修改权限。

reader 核对 journal 的 Nginx 进程/unit/标识和登记 profile 摘要，限制时间、条数及输出。当前 12 KiB 投影预算可能在密集窗口产生裁剪；此时显示缺口，错误比例规则不使用偏斜残片。扫描规则可以保留已见事件的下界证据。

事件按主机作用域和 journal cursor 去重，Web 独立存于 `web-security.sqlite3`。已阅不表示问题解决，恢复采集不删除历史失败。SSH 与 Web 共享轮询租约及采集锁，分别展示状态；原有 SSH 作用域、报告和基线保持兼容。

## AI 接口

部署端同时配置 `OPSARK_AI_BASE_URL`、`OPSARK_AI_MODEL`、`OPSARK_AI_KEY`，兼容接口须支持所需 JSON 模式。0.6 初验时尚未配置凭据，当时真实模型调用为零；后续真实模型接入见[AI 补丁记录](AI_PATCH_EXECUTION.md)。本页新增的 0.18 本地 503 反例独立使用假凭据，不代表供应方推理效果。

| 接口 | 行为 |
| --- | --- |
| `GET /api/security/alerts/{id}/analysis-input` | 返回发送预览、输入摘要、模型名及提供方主机 |
| `POST /api/security/alerts/{id}/analyze` | 需要 `{confirm_send:true,expected_input_digest:摘要}`；事实、模型或提供方变化返回 409 |

接口均需认证。模型输入使用主机、站点及来源的临时别名，只含允许的类别、数字、UTC 时间和证据引用；不发送真实 IP、域名、账号、日志游标或配置。

程序校验输出结构、动作类别与引用，拒绝工具调用、未知引用和额外执行参数。输出固定 `actions_executable:false`，仅建议补证据、核查访问、源站防护、评估限流/挑战/敏感路径规则或联系上游 DDoS 防护。

只持久化与当前输入匹配的完成建议；新事实或提供方变化后旧建议失效。超时、失败及无凭据不覆盖已有有效建议。这些建议尚未连接实际执行器。

## 实际验证及未覆盖部分

- 0.6 CI 八个任务全部通过，覆盖三系统控制端、三浏览器和 Ubuntu/Debian 管理端实验，不等于生产检测准确率。
- 两台正常请求、静态资源、自称爬虫及业务回调返回预期响应；每台 12 个正常/伪造来源事件未产生 Web 行为告警，伪造 IP 未被采信。
- 每台 12 次受控 503 在完整窗口形成错误告警，保留 12/18 的匹配/观察样本指标。
- 每台 6 次敏感路径探测及 6 次携带自称爬虫 UA 的探测形成一个扫描告警，唯一事件计数 12。四个 Web 演练告警均通知一次，重叠读取未重复计数。
- 实际 API 核对四个告警、来源、分类模型输入、无凭据返回和已阅。观察中确实出现过裁剪和间歇 SSH 采集失败，已独立保留缺口。
- 常驻控制端升级到 0.6.1 后，四个告警计数、通知次数和已阅状态保持；两台 SSH/Web 通道重新成功采集，作用域一致。
- Chromium 回归覆盖五种宽度、Web/AI 合成契约、事实变化重新确认及退出会话。合成输出不等于真实提供方联调。

实机操作及明细留在 Git 忽略的部署目录。公网代理链、真实共享出口、高峰流量、外部通知和实际防御生效仍待分别验收。

## DDoS 与静态兜底

自有静态维护页可承接合法访问的故障兜底，网络清洗须由上游防护承担。HTTP 跳转需要源站先收到请求且客户端跟随，不能移走直接 IP、UDP/SYN 或占满链路的流量。GitHub Pages 有带宽及使用限制，不能作为任意攻击流量接收池。[Pages 限制](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

后续结合已授权的 CDN/WAF、源站访问限制及服务商 DDoS 能力，分别验证网络层和 HTTP 路径。[Cloudflare DDoS](https://developers.cloudflare.com/ddos-protection/)、[源站保护](https://developers.cloudflare.com/fundamentals/security/protect-your-origin-server/)

日志使用 JSON 转义及 Unix syslog `nohostname`，真实部署已按官方语义修正消息格式。[Nginx 日志](https://nginx.org/en/docs/http/ngx_http_log_module.html)、[syslog](https://nginx.org/en/docs/syslog.html)
