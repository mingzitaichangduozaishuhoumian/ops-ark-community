# SSH 防护工作器的后续阶段

2026-11-06 的源码研究与验收边界。第一阶段[原任务只读跟进](DEFENSE_TASK_WATCH.md)和第二阶段[单次自动会话](DEFENSE_SINGLE_SESSION.md)均已默认关闭实现，并有各自实机记录；新 Root 生命周期、长期授权与公网范围仍待设计、验收。现有 `OPSARK_DEFENSE_WORKER_ENABLED=true` 仍拒绝启动，持续执行能力标志保持 false；原补丁/漏洞持续观察的能力不代表本通道已经支持。

## 当前协议限制

Root v1 的观察许可是一次性的。成功 arm 后，既有 cursor 的非空 payload 会拒绝后续 arm，即便已 consumed 或 expired；换 RID、删除账本、重建 scope 或重新初始化不能作为续期办法。观察窗固定 120 秒、动作 TTL 固定 60 秒，每 cursor 最多一个 action。Root 还有 8 cursor、8 action 和 32 mode RID 的容量上限，拒绝记录也占容量。现协议没有许可续发、轮换或归档入口。

因此在不改 Root 协议和权限的前提下，只能增加原任务跟进，或在管理员明确 arm 后运行一次有界自动会话，不能称长期持续自主防御。到期不补加 TTL，未知状态不因内核集合为空而算已完成。切换手动或停止工作器只阻止新动作，不保证撤回在途动作；撤销仍有独立的精确确认。

## 第一阶段：原任务只读跟进

已实现显式独立开关、认证本地界面、状态迁移告警及已阅；最多一次 RPC/tick，带跨进程 lease/claim 与原观察落库的原子 fence。手动模式允许只读跟进，不触发新动作或模型。登记历史分批追赶时明确显示未完成，预算与记录容量均有持久上限；具体合同见[说明](DEFENSE_TASK_WATCH.md)。

两台新隔离环境的[实机结果](../tests/defense_task_watch_lab/README.md)已分别核对：后台自动查询原 RID、手动跟进至到期、已阅与第三进程重启保持预算和事件，界面无 HTTP query 替代，业务未复验继续待验收。它只证明本阶段，不使以下单次自动动作或长期授权方案自动成立。

- 只查询已登记、已持久化的同一原 RID，保留原清单、发送 owner、费用和 latch。重启不接管旧发送许可，不自动 prepare/apply/revoke，也不新增模型调用。
- 使用持久化 worker 租约和唯一 owner，限制全局并发、单目标在途数、调用频率及退避。目标或公开信任材料变动时停止远程查询，保留本地历史并报证据缺口，不另换目标或凭据。
- 通过固定枚举记录确认、未知、不可用、自然到期及恢复，告警按原任务与状态迁移去重。摘要不携带来源原文、原始日志、路径或凭据；外部通知要另行配置。
- 验收正常跟进、重复 tick、并发双 worker、租约丢失、断线、真实进程重启及目标退役。安装/执行次数、原授权和原账本不变；查询不能给旧业务复验续期。

## 第二阶段：明确 arm 后的单次自动会话

[单次自动会话候选](DEFENSE_SINGLE_SESSION.md)已完成默认关闭的 API/界面：同 boot/首次 lease epoch/原 Controller 窗口绑定，费用、派发及回执原子 fence，AI20秒/RPC10秒上限，停止和未知只读对账。固定版本 368 项联合回归、后续驱动 33 项回归分别通过。两台各在新 auto profile 完成规则正常 ACK、真实模型正常 ACK、真实 socket 丢 ACK，第二进程只读原任务；业务始终待验收。独立失败及修正保留在[实机记录](../tests/defense_session_lab/README.md)，没有用旧半自动结果替代本阶段验证。

- 先核 automatic、两层 grant、Root 模式完整 ACK 与当前绑定，再由管理员显式 arm。tick 不调用会递增 sync_generation 的 `sync_mode()`；版本或 generation 变动即停止新动作。
- worker 租约的 owner/CAS fence 必须贯穿 AI 费用预留、最终准入、prepare/apply 的 `begin_sendable` 和实际 SSH exec/send。现有 Store 有 lease 参数，不等于上层已经接线；只在外层拿租约不能防止过期 owner 发送。
- AI 与执行预算分开，每份原证据只占一次分析费用。严格 proof 过期、计数变化或另一来源出现时，要求 AI 的策略必须停下，不能改分析 ID 重新收费或退化为未经授权的规则执行。
- 串行且有整会话预算，先核剩余观察窗再调用。单次会话 AI 最多 20 秒，查询与 prepare/apply 各最多 10 秒；还按原证据剩余时效收紧模型超时，纯阶段有界推进，需要时只读刷新同一 cursor 并核全部证据不变。刷新也占原剩余预算；不能保证晚到候选赶上 120 秒，更不能靠续窗解决。原显式接口的默认预算与本会话上限分开。
- 验收人工停用、grant 过期、预算不足、租约换主、各发送阶段进程中断和未知回执。只允许一个原 action；所有旧 owner 已发送、sendable 或 unknown 任务在重启后只查询，不重放。

## 第三阶段：独立的新 Root 生命周期协议

长期观察需先设计新版本协议：管理员明确授权的许可续发、严格容量与拒绝记录预算、不会清空使用量的归档及可审计墓碑、跨重启持久化、模式轮次和并发 fencing。Agent 执行角色不能获得签发自己新许可或任意改账本的能力；旧 v1 原件和历史不可被新协议采用或重写。

新协议须另有负面测试和两台新隔离环境的实机验收，再讨论扩大地址、IPv6、公开入口和持续部署。当前容器可写层实验不证明容器重建或宿主恢复；公网流量防护与上游 DDoS 容量也不能由此推导。

两台已分别通过[22423 Root 协议传输重启验收](../tests/defense_transport_lab/README.md)：保留 22422 被保护服务、netns、日志及原账本，监督器只替换持有的进程一次，零重新初始化或续发授权。第一控制端退出后，第二进程只查询原 RID，usage/intent/期限不变，没有新增 arm/prepare/apply。冻结 Root v1 的查询纯读，故本轮还核对 Root ledger 全字节一致；Controller 只追加合法查询观察，原执行原件不变。248 项联合回归及双机结果分别留证，模型调用为零、业务待验收、实验已清理。

上述仅证明传输通道恢复。受保护服务重启会改变 PID、启动时间及 socket inode，现 v1 应保留未知并拒绝新动作；后续需对该否定路径独立实测。容器重建和宿主重启仍需独立协议，不能重算旧单调时钟期限。
