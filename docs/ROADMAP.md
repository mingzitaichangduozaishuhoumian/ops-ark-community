## 阶段零 用户任务和流程验证

交付物：网站接入、事件调查、动作预览和验收报告样例；已知故障案例目录；初始环境与权限清单。

先联系 5 至 8 位维护客户网站的人，复盘最近三次真实故障。记录排查入口、收集证据和确认恢复的时间、误判、使用过的工具，以及接入真实机器的顾虑。人数为初始招募目标。

退出条件：

- 明确首批场景的用户任务、支持子类、不能判断时的交付结果。
- 网站、依赖、证据和验收样例能由用户理解并用于复核。
- 有用户愿意提供脱敏案例或接入测试机器；记录实际接受的权限边界。
- 若只有口头兴趣，继续验证接入意愿，不据此扩大实现范围。

## 阶段一 只读诊断与安全观察

交付物：固定环境中的 SSH 接入、依赖确认、基线、三类故障调查、结构化证据与无业务写入的检查；安全事件只记录检测结果及建议动作。OpsArk 不新建或扩大阻断，原有防护按原策略运行，实际动作与建议动作分开记录。

退出条件：

- 首批故障案例均能给出可复核事实；证据不足、日志缺失和不支持环境能正确停止并交付下一步检查。
- 变更结论能追溯到真实历史记录，冷启动不会编造历史。
- 安全观察覆盖正常高峰、爬虫、共享出口和业务回调，区分攻击尝试与入侵判断。
- 记录接入耗时、调查耗时、人工介入、资源和模型成本，形成后续阈值依据。
- 同时记录目标业务、相关站点与正常访问结果，能够导出完整事件记录。

## 阶段二 人工批准的结构化处置

首个已实现的动作是 Ubuntu 官方安全单包升级，隔离 guest 的半自动真实安装及复扫已经通过。0.9 另完成了一次预授权自动升级及修复后实机验证，未覆盖的故障与恢复对照继续单独验收。两条通道都只覆盖本机架构、无声明 conffiles 和额外依赖变化的允许名单包；不自动重启主机、封禁或限流。按[自主修复合同](VULNERABILITY_REMEDIATION.md)及[自动修复条件](AUTOMATIC_REPAIR.md)逐项验收后，再增加 Nginx 配置重载及可信恢复设计；配置备份和包降级不能统一承诺完整回滚。

退出条件：

- 具体动作与授权绑定；配置变化、过期授权和冲突操作均被拦截。
- 执行前后状态、失败和中断可追溯；重试不会重复执行未知结果的修改。
- 在实验环境验证配置恢复和管理通道恢复，覆盖当前文件已被外部修改及缺失有效回退点的情况，不将命令成功作为完成验收。
- 一项动作通过后再增加下一项，容器操作逐项验证状态与数据影响。

## 阶段三 预授权防御试用

预授权单包补丁的实现与实机验收见[自动修复合同](AUTOMATIC_REPAIR.md)。限时 SSH 来源阻断已在 IPv4 回环和 Docker 内部桥接路径实测。独立管理端经真实 TCP 复位丢失回执后可重新查回原动作，重复执行不续期。内核到期和确认撤销分别恢复 SSH，管理访问和同源非 SSH 端口保持可用。实际控制台已通过固定只读 SSH 回查、监听器中断和自身重启的隔离验收。该执行器仍用于源码仓库内的隔离实验。公网、IPv6、Docker 发布端口和控制台写侧提交仍需单独验收。[SSH 阻断实验](../deploy/defense/README.md)

退出条件：

- 每份策略明确目标、触发条件、期限、数量上限、白名单、撤销及授权撤回方式。
- 实测 TTL、本地解封、人工撤销、控制台失联、模型超时及事件洪峰。
- 对实际流量路径证明规则生效，验证管理访问和已登记合法业务请求。
- 误封、未知来源或影响范围不明时，停止扩大自动动作并交付人工调查。
- 试用记录包含有效处置、误报误封、业务影响和用户再次使用情况；达到基于观察数据制定的门槛后才扩大试用。

## 首批验证案例
