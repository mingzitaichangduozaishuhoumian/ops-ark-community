# 隔离 tmpfs 磁盘调查验收

在授权的一次性 Linux Docker runner 上，使用预先准备且按镜像 ID 固定的 Ubuntu/Debian 镜像。镜像需有系统 Python 3、GNU chroot、GNU df/nice/du/timeout、ldd 和静态 BusyBox。初始化器复制这些 GNU 工具及经核验的动态链接依赖，其他受限命令只使用实际存在的 BusyBox applet。

```console
uv run python tests/filesystem_lab_smoke.py --image sha256:<固定实验镜像> --confirm-isolated
```

实验依次创建两个随机名称、带独立标签的容器。根文件系统只读、网络为 `none`，能力仅保留 `SYS_CHROOT`，限制为 192 MiB 内存、零额外 swap、0.25 CPU 和 32 个进程。Docker 私有 tmpfs 提供实验根和状态目录，容器不挂载宿主路径、数据卷或 Docker socket。

实验 PID 1 回收子进程并设定 300 秒最长生命周期，避免测试控制器退出后留下长时间运行的负载。

容量实验根为 32 MiB、256 个 inode，覆盖日志分配、业务数据分配，以及删除路径后仍由真实文件描述符持有的占用。inode 实验使用独立的 2 GiB 逻辑上限和 256 个 inode，只创建有界数量的零字节文件。它的实际分配仍受 192 MiB memcg 限制，要求 inode ENOSPC 时可用字节数超过 1 GiB，避免同时触发容量阈值。

控制台通过临时固定指纹 SSH 桥，调用原有 `/api/investigations` 磁盘场景。桥只允许该场景生成的五条精确命令，并将其固定映射到不可变容器 ID 内的 chroot。OS、工具、df 和 du 都从实验根读取。宿主机目录、日志和磁盘不参与这些命令。

正常 API 保存观测基线，后续报告对照真实容量和 inode 变化。日志与业务目录需保留不同分类。删除后仍占用的文件由实验控制程序证明，产品报告继续标注开放文件引用和实际可回收量未核实。32 MiB 实验根始终低于产品现有的 1 GiB 可用空间阈值，所以正常与复原快照也可能显示需要关注。复原只核对实验文件系统测量值，业务恢复继续留待验收。

程序核对完整 SSH 证据和生产解析器结果，不改写原生 df/du 输出。遇到不兼容的工具格式、资源或挂载范围不符时停止。退出时核对容器 ID、镜像和本次标签，只清理本次对象；最终输出为有界的验收布尔值。

最小根中的挂载目录记录只描述已核验的 tmpfs，容量和 inode 数字仍由工具读取实际内核文件系统状态。GNU inode 表头保留原样。初始化后，先运行正常采集，再用独立 statvfs 读数核对基线。

2026 年 11 月 5 日，授权测试机完成日志增长、业务数据增长、删除后仍持有的 df/du 差异、字节空间充足时的真实 inode ENOSPC，以及复原后的测量值对照。临时 SSH 桥和正常调查 API 均使用真实命令结果，产品原有缺口仍保留。原容器和网络在实验前后核对一致。
