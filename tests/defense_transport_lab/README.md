# Root 协议 SSH 传输重启验收

2026-11-06，两台授权测试机分别在新隔离环境通过同一固定版本 `85be63098725ac065a3764e33330c2ab65754dd4`。本轮只重启容器内承载 Root 协议的 `22423` sshd，不重启被保护的 `22422`、容器、宿主或常驻实例。

每份流程为：真实控制台明确切换模式与 arm → 启动一次自动规则会话 → 正式后台 prepare/apply 各一次并直接收到 accepted ACK → 第一控制端进程退出 → 独立监督器替换一次持有的 `22423` 子进程 → 第二控制端进程登录并只查询同一个原 RID。浏览器没有手动 prepare/apply；第二进程只有一条 query 写请求，没有重建观察、执行、撤销或模型调用。

## 独立证明的边界

- 旧 `22423` 进程已按持有的 PID/启动身份及 pidfd 回收，新进程和监听 socket 身份确实不同；启动失败的已生成子进程也有清理身份。没有在途连接才允许重启。
- 被保护的 `22422` PID、启动时间、socket、网络命名空间、认证日志、公开 pin、私钥文件元数据、配置、三角色公钥/固定入口和 sudoers 原件保持。私钥正文不读取、不计算内容哈希。
- 新旧 Root ledger 全字节相同，原 deployment/grant、引用、使用量、意图、绑定及期限保持；初始化、provision、nft 初始化和生成 Hostkey 的重启调用增量均为零。该字节加强门禁适用于本轮冻结 Root v1、无并发修改的稳态，不是未来生命周期协议永远不写账本的承诺。
- Root query 对该冻结实现是纯读，`deadline_at` 保持原 manifest UTC。查询后剩余 TTL 只能下降或自然到期，不把到期改成新授权。控制端允许追加合法查询观察，原请求、清单、费用和授权原件不变。
- 两台各一次执行、一次传输重启，Root usage/intent 各一；总四个真实控制端 Python 进程，实际模型调用零。没有业务复验或人工撤销，交接摘要继续待验收。

旧 15 文件逐字节不变，仅新增第 16 个受限实验入口。四容器、三处目标挂载、各 `192 MiB / 0.5 CPU / pids 96`、600 秒容器生命周期及 480 秒工作加 120 秒清理预算沿用原范围。固定本地中继不发布宿主端口，外层 admin 只使用授权测试机。读取实验私钥前先核对 namespace、资源、目录和文件身份，越界路径在 SFTP 前拒绝。外层正常停止和受控故障终止均不接管其他进程。
